ERD Designer

A Visio-style database model diagram tool. Drag entities onto the page, give every column a data type and the right constraints (PK, FK, NOT NULL, UNIQUE, DEFAULT, CHECK), connect relationships from parent to child, set the cardinality and referential actions — then validate the model, generate the SQL and prove your constraints work with real test rows. All organisations and people are fictional.

Constraint cheat sheet

PRIMARY KEYUniquely identifies each row. Never NULL, never repeated.
FOREIGN KEYMust match an existing primary key in the parent table (or be NULL if optional).
NOT NULLA value is required (shown in bold).
UNIQUENo two rows may share a value — e.g. email addresses.
DEFAULTValue used when none is given — e.g. 'Booked', 0, CURRENT_DATE.
CHECKA business rule — e.g. Price >= 0, Size IN ('S','M','L').
ON DELETECASCADE deletes children too · RESTRICT blocks the delete · SET NULL blanks the FK.
