Vigenère cipher

A keyword gives a different Caesar shift for each letter (A=0, B=1 …). The same plaintext letter can become different ciphertext letters, which flattens the frequency chart and defeated simple frequency analysis for 300 years.

Still breakable: the keyword repeats. If an attacker works out the key length (e.g. with the Kasiski test), the message splits into several ordinary Caesar ciphers — each can be broken with frequency analysis. Modern ciphers like AES have no such pattern.

Live hashing and the avalanche effect

A hash function turns any input into a fixed-size "fingerprint". These hashes are calculated for real with crypto.subtle.digest().

SHA-1 is broken: in 2017 researchers produced two different PDF files with the same SHA-1 hash (a collision). Browsers stopped trusting SHA-1 certificates. Use SHA-256 or better.

Properties of a good hash

➡️ One-way

Easy to compute the hash, but no way to run it backwards. The only way to "reverse" a hash is to guess inputs and compare — which is why weak passwords are at risk.

📏 Fixed length

Whatever the size of the input, SHA-256 always gives 256 bits (64 hex characters).

🧩 Collision resistant

It should be infeasible to find two inputs with the same hash. For SHA-256 that would take around 2128 attempts — far beyond every computer on Earth. Also deterministic: the same input always gives the same hash.

File-integrity check

Software sites publish a file's SHA-256 so you can check your download hasn't been altered. Paste the contents of two "files" and compare their fingerprints.

Slow hashing with PBKDF2

PBKDF2 repeats a hash many thousands of times. One login takes milliseconds, but an attacker making billions of guesses is slowed down by the same factor. (bcrypt, scrypt and Argon2 do the same job.)

Why salts defeat precomputed tables

An attacker can hash millions of common passwords once, in advance, and store a lookup table of hash → password (a "rainbow table" is a compact version). With plain hashes, every stolen hash can be looked up instantly, and identical passwords stand out.

hash("Summer2026!")
= 8f1c…
found in table ✔
→
hash("x7Qp…" + "Summer2026!")
= 2be0…
not in any table ✘

A salt is a random value, unique to each user, stored next to the hash. It is not secret. Because every user's input is different, a table made in advance is useless, and the attacker must start again for every single account. Same password, different salt → completely different hash.

Salt + slow hash together: no shortcuts, and each guess is expensive.

    ECDSA: digital signatures

    The sender signs with their private key; anyone can verify with the public key. A valid signature proves who sent it (authenticity) and that it hasn't changed (integrity), and the sender can't deny it (non-repudiation).

    Certificates and the chain of trust

    A certificate binds a domain name to a public key, signed by a Certificate Authority (CA). Your browser trusts a small set of root CAs; roots sign intermediates, which sign site certificates. Pick a site, open its certificate, then decide what (if anything) is wrong.
