The normal forms in one line each

0NFUnnormalised: repeating groups — several values crammed into one row (like the lines on an order slip).
1NFEvery cell holds one value, no repeating groups, and every row has a primary key.
2NF1NF, and no partial dependencies: every non-key column depends on the whole key.
3NF2NF, and no transitive dependencies: non-key columns depend on nothing but the key.
🗝️ “The key, the whole key, and nothing but the key.” 1NF needs a key · 2NF: the whole key · 3NF: nothing but the key.

Dependency diagram — Hilltop Café in 1NF

An arrow means “determines”: if you know the value at the tail, there is only one possible value at the head. Arrows from part of the key are partial dependencies; arrows from a non-key column are transitive.

Workbench — build the tables yourself

No steps, no hints: create tables, click columns into them, mark the keys, then press Check my design. Any correct 3NF design passes — it doesn't have to match a model answer.

Data dictionary

A data dictionary describes every field before you build anything: its data type, its key and how it will be validated. Use the sample data to decide. Tip: phone numbers and codes like C07 are Text — they can start with 0 and you never do maths with them.

From design to SQL

The dictionary turns straight into SQL. Parent tables are created first, because a foreign key can only point at a table that already exists.

-- Check your data dictionary, then press Generate.

ERD builder

Each table becomes an entity. Draw a relationship for every foreign key, then set the multiplicity at both ends. Drag boxes to tidy the layout.

Rule of thumb: the table that holds the foreign key is on the many side. The table it points to is on the one side.

1 · Say it both ways

Every relationship has two directions. Read the business rule, finish both sentences, and watch the notation draw itself.

2 · Quick-fire: one or many?

0 / 0

20 everyday pairs. Decide the relationship type, then read why. Aim for 15 or more.

3 · Prove it with the data

Don't guess — look at the rows. Each table shows real pairs from a system. Answer the two questions and the data will prove (or disprove) you.

4 · Spot the mistake

Each ERD has one wrong multiplicity. Read the rule, click the wrong end, then choose the right value.
