Anatomy of a route

A routing table doesn't store single addresses — it stores whole networks. Read each entry left to right:

S   192.168.1.128/26  [1/0]  via 10.0.0.6,  Gi0/1
S — code letterHow the route was added (not how good it is).
192.168.1.128 — network IDThe network this entry represents.
/26 — subnet maskHow many bits are the network part (255.255.255.192).
[1/0] — admin distance / metricTrust in the source / cost of the route.
via 10.0.0.6 — next hopThe IP of the next router to send the packet to.
Gi0/1 — interfaceThe router's own port the packet leaves by.

Code letters you'll see

CDirectly connected — the router reaches it through its own interface, so no next hop.
LLocal — the interface's own exact address (/32).
SStatic — typed in by an administrator with ip route.
OOSPF — learned dynamically from an OSPF neighbour.
RRIP — learned dynamically via RIP.
DEIGRP — learned dynamically via EIGRP.
S*Candidate default — a static default route.
*The route currently chosen as the default.

How the router chooses

To forward a packet, the router compares its destination IP against the network ID + mask of every entry, then applies these rules in order:

1. Longest prefix match. If more than one entry matches, the router uses the one with the longest (most specific) mask — e.g. a /26 beats a /24 for the same address.
2. Administrative distance. If it learned the same network from two sources, it trusts the lower AD — e.g. a static route (AD 1) is preferred over OSPF (AD 110).
3. The default route (0.0.0.0/0). Matches everything, but only wins when nothing more specific matches — normally the way out to the internet.
No match at all? With no default route, the router simply drops the packet.

Static vs dynamic — the difference the exam asks for

Static routes are added by hand (ip route …) and never change unless edited — simple, secure, predictable, good for small networks. Dynamic routes are built automatically by a protocol (RIP/OSPF/EIGRP) and update themselves when links change — better for large, growing networks, but need more processing and care. The code letter tells you how a route was added, not how good it is.
