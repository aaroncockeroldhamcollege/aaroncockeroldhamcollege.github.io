Active Directory Lab

Run a small Windows domain the way a network technician does: build OUs, users and groups, follow AGDLP to grant access to file shares, and control desktops with Group Policy. Learn the rules, practise the reasoning, then administer a Windows Server 2008 R2 domain controller and log on to the client PCs to see the results.

Domains, forests and OUs

Active Directory Domain Services (AD DS) is a database of every user, computer and group in an organisation, held on servers called domain controllers (DCs). Users log on once, to the domain, and every PC and server trusts the DC to check their password.

Forest — one or more domains that share a schema and trust each other. It is the real security boundary.
Domain — a named administrative unit with its own DNS name (here oakfield.test; NetBIOS name OAKFIELD). Users log on as OAKFIELD\j.smith or j.smith@oakfield.test.
Organisational unit (OU) — a folder you create to organise objects, usually by department or location. You can link Group Policy to an OU and delegate control of it.
Containers are not OUs. The built-in Users and Computers folders are containers: you cannot link a GPO to them. Move accounts into OUs to manage them with policy.

The global group says who someone is (their role). The domain local group says what access it represents. When a new salesperson starts you only add them to GG_Sales — no folder permissions ever change. A global group cannot contain a domain local group, so nesting the wrong way round is refused.

Share permissions vs NTFS permissions

Share permissionsNTFS permissions
Set onThe shared folder (Sharing tab → Advanced Sharing → Permissions)Any folder or file (Security tab)
Apply whenOnly when connecting over the network (\\FS01\Sales)Always — over the network and when logged on locally
LevelsFull Control · Change · ReadFull control · Modify · Read & execute · List folder contents · Read · Write
DefaultEveryone: Read (2008 R2)Inherited from the parent folder
Over the network, the most restrictive wins. Work out the share result and the NTFS result separately, then take whichever is less. Share Read + NTFS Modify = Read.
Within one list, permissions add up. A user in two groups gets both groups' allows combined: Read + Write = Read & Write.
An explicit Deny wins. If any of your groups is denied a permission, you lose it even if another group allows it. Use Deny sparingly — usually it is better simply not to grant access.
Common practice: set the share to Everyone / Authenticated Users: Full Control or Change and do the real control with NTFS. In this lab you will remove Everyone and use your DL groups on both.

Inheritance

New folders inherit the NTFS permissions of their parent (shown greyed out). To change an inherited entry you must disable inheritance (Security → Advanced → Change Permissions → untick Include inheritable permissions from this object's parent), then choose Add (convert the inherited entries into explicit ones you can edit) or Remove (start with an empty list). An explicit Allow on a folder overrides an inherited Deny from above.

Group Policy and LSDOU

A Group Policy Object (GPO) is a bundle of settings. It does nothing until it is linked to a site, the domain or an OU. Computer Configuration applies to computers in that OU at start-up; User Configuration applies to users in that OU at log-on. PCs also refresh policy every 90 minutes, or straight away with gpupdate /force.

DDomain
OOU (parent)
OUchild OU — applied last
Applied in order L → S → D → OU. If two GPOs configure the same setting, the one applied last wins — so the OU closest to the object usually wins.
Link order — when several GPOs are linked to the same OU, link order 1 has the highest precedence (it is applied last).
Block Inheritance (on an OU) — stops GPOs linked higher up from applying to that OU.
Enforced (on a link) — that GPO cannot be blocked and wins over conflicting GPOs lower down. Enforced beats Block Inheritance.
Security filtering — by default a GPO applies to Authenticated Users. Replace that with a group so it only affects members of the group.
Password and account lockout policy for domain accounts only comes from GPOs linked to the domain (normally the Default Domain Policy).
gpresult /r lists the GPOs that applied to the logged-on user and computer, the ones filtered out and why, and the user's groups. Group membership changes need the user to log off and on again.
