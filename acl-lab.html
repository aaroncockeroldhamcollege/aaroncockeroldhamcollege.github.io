ACL Lab

How a Cisco IOS router filters traffic with access control lists: standard and extended ACLs, wildcard masks, where to put them and which direction to apply them. Learn the rules, practise writing them, then configure a router yourself and send packets through it to see what gets through.

Standard vs extended ACLs

An access control list is an ordered list of permit and deny statements (ACEs). The router compares each packet with the list when it enters or leaves an interface.

How the router processes an ACL

Top-down, first match. The router reads the ACEs in order and stops at the first one that matches. Later lines are never checked, so put specific lines above general ones.
The implicit deny. Every ACL ends with an invisible deny any (standard) or deny ip any any (extended). If nothing matches, the packet is dropped. An ACL with only deny lines blocks everything.
Sequence numbers. ACEs are numbered 10, 20, 30… In a named ACL (or ip access-list standard 10) you can insert 15 deny … between two lines, remove one with no 20, and renumber with ip access-list resequence. Typing no access-list 10 deletes the whole numbered list.
The three Ps. One ACL per protocol (IPv4), per direction (in or out), per interface. Applying a second ACL in the same direction replaces the first.
In or out? in checks packets as they arrive on the interface, before routing. out checks packets as they leave the interface, after routing. Packets the router creates itself (like its own pings) are not checked by outbound ACLs.
Not stateful. A router ACL doesn't remember connections. The reply is a new packet and is checked against any ACL on its way back. Use established to permit TCP replies (packets with the ACK or RST bit set).

Where should the ACL go?

Standard → close to the DESTINATIONIt can only see the source address. Put it near the source and it would block that source from everywhere, not just the network you meant to protect. ip access-group 10 out on the interface facing the protected LAN.
Extended → close to the SOURCEIt can match the exact destination and service, so drop unwanted traffic as early as possible and don't waste bandwidth carrying it across the network. ip access-group NAME in on the interface where the traffic arrives.

Wildcard mask calculator

A wildcard mask tells the router which bits to check. 0 = must match, 1 = ignore. For a subnet, wildcard = 255.255.255.255 − subnet mask. Type an address and a wildcard, or pick an example.
